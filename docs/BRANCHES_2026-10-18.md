## Retiring the old branches without losing them

Run once, from a clone with push rights. Each branch is first saved as a tag at the same commit, and the script stops if a tag does not resolve to the branch tip.

```bash
git fetch origin --tags
for b in archive/five-paper-core-2026-09-20 ch12-freeze-transfer fix/restore-proposal-spacing-benchmark-20260915 \
         proposal/balanced-10pp-review-20260915 render/current-proposal-c788ba0 research/full-version-comparison-20260916 \
         research/issuer-admission-policy-20260915 research/economic-contribution-20260910 research/longitudinal-review-20260909 \
         research/issuer-movement-bridge-20260910 research/empirical-certification-v2-20260910 \
         research/empirical-certification-integration-20260910 research/research-synthesis-20260910 \
         research/empirical-robustness-20260910 research/results-consolidation-20260912 research/sol-independent-concept-20260911; do
  t="snapshot/${b//\//-}"
  git tag -a "$t" -m "Snapshot of $b, retired 2026-10-18. Restore: git branch $b $t" "origin/$b"
  git push origin "refs/tags/$t"
  [ "$(git ls-remote origin "refs/tags/$t^{}" | cut -f1)" = "$(git rev-parse "origin/$b")" ] || { echo "tag mismatch for $b"; exit 1; }
done
# only after the loop finishes with no error:
# git push origin --delete <branch> ...      (the same list)
```

To bring one back: `git branch <name> snapshot/<name with / replaced by ->` then push it.
